1. zstd: removed from macOS, Linux, Android and iOS configuration, compilation and non-Windows packaging.
   Its only project calls are ZSTD_findFrameCompressedSize, ZSTD_isError, ZSTD_decompress and ZSTD_getErrorName
   inside the _WIN32 branch of nr_native::ExtractCode in src/engine/render/upscale/neural_native.cpp.
   The non-Windows branch returns "Windows only". Windows keeps the pinned decompressor for DLSS GPU bundles.
   Evidence before edit: /Users/suporte/PT-Mac/build/dependency-audit/zstd-uses-before.txt
   Current compile_commands.json for both Apple builds has zero zstd sources. Fresh configuration needs no zstd cache.
   Removed stale generated notices as well, so reusing a build does not keep packaging the retired non-Windows license.

2. macOS vulkan-loader: removed from the Homebrew CI recipe and build documentation.
   CMake now discovers headers and the host glslc directly on both Apple platforms. The engine loads MoltenVK directly.
   No Apple target links Vulkan::Vulkan. glslc links only system libraries; the installed shaderc formula has no runtime dependencies.
   Evidence: /Users/suporte/PT-Mac/build/dependency-audit/pt-baseline-link.txt
   Fresh configuration with CMAKE_DISABLE_FIND_PACKAGE_Vulkan=ON and no Vulkan_LIBRARY cache entry passed:
   /Users/suporte/PT-Mac/build/dependency-audit/mac-no-loader/configure.log
   Windows/Linux loader requirements are retained: Linux FFX links Vulkan::Vulkan; Windows discovery still uses FindVulkan.

3. ImGui demo component: removed imgui_demo.cpp from pt_thirdparty.
   Searches for ShowDemoWindow, ShowStyleEditor, ShowUserGuide, ShowStyleSelector and ShowFontSelector found no project callers.
   The only demo-path match was its CMake source list. Both game executables and every test linked successfully without it.
   Evidence: /Users/suporte/PT-Mac/build/dependency-audit/imgui-demo-uses-before.txt
   The real ImGui UI/backends and their source download remain needed. The demo was already omitted from executable code by the linker.

4. stb_vorbis: removed its only implementation include and redirected ALL three decoding paths to libvorbis.
   Canonical choice: libvorbis already decodes the game's Wwise audio. Added its bundled vorbisfile.c container reader,
   with a memory callback adapter; this introduces no new downloaded dependency. stb image/font components remain.
   New code: src/engine/audio/ogg_vorbis.cpp, 59 physical lines; declaration header, 11 lines.
   This is codec integration code, not a new homegrown codec. None of the remaining libraries is a safe few-dozen-line substitute.
   Tests were added and passed WHILE the old stb decoder still existed, then callers were migrated and tested again.
   tests/ogg_vorbis_test.cpp checks synthetic mono/stereo/surround data, rate/channel/count/content, limited prefixes,
   complete decoding, chaining, malformed/truncated input, output reset and the actual Lisa music entry points.
   The three small Ogg fixtures are generated sine waves, with source and provenance in tests/fixtures/vorbis/.
   No codec, FFmpeg or encoder installation is needed to run the tests.
   Before/after parity: complete 6,510,643-frame game music track and five prefixes have identical frame counts, channels
   and rate, with at most ONE 16-bit PCM unit difference. Synthetic mono matches exactly; stereo differs by at most one unit.
   This is not a bit-identical decoder change. The six-channel fixture exposed severe clipping/distortion in the old stb decoder.
   The canonical decoder matches FFmpeg within one PCM unit over their common output after channel-order mapping;
   FFmpeg emits 128 fewer frames for that fixture. The test independently checks encoded tone content and full input duration.
   Evidence: /Users/suporte/PT-Mac/build/dependency-audit/vorbis-parity-game.log
   /Users/suporte/PT-Mac/build/dependency-audit/vorbis-parity-fixtures.log (includes the old surround-decoder failure)

   Final repo search finds zero stb_vorbis references in code/build/tests/tools; nm finds ov_read and no stb_vorbis symbols in pt.

BUILD TOOLS AND TRANSITIVE DEPENDENCIES
CMake/Ninja, Clang/LLVM/MSVC/Xcode tools, Python and Git are used by configure, compile, shader, packaging and pinned-source steps.
Shaderc/glslc and SPIRV-Tools compile/optimize shaders; SPIRV-Cross translates to HLSL; DXC/dxv compile/validate DXIL.
These tools perform consecutive transformations, not interchangeable implementations of the same output.
.NET 10/Android workload, Android SDK/NDK/build-tools, Java tooling and Xcode SDKs build their platform launchers and native modules.
The cached extractor restore graph contains only the LibOrbisPkg.Core project reference; no third-party NuGet PackageReferences.
Whisper embeds ggml. Its KleidiAI, CUDA, Vulkan, OpenMP, Metal and curl download paths are OFF in both audited Apple caches.
Upstream example/research requirements and disabled backends were not treated as installed project dependencies.
Vendored implementation pieces (SDL hidapi and platform backends, zstd xxhash on Windows, ggml CPU kernels, SPIR-V headers)
are consumed inside their parent libraries. They are not redundant independently installed packages.

All 36 Linux sysroot roots were checked against compiler/runtime requirements and SDL platform probes:
  libc6-dev, linux-libc-dev, libgcc-14-dev, libstdc++-14-dev, libgcc-s1, libstdc++6, libc6, libx11-dev, libxext-dev, libxrandr-dev, libxrender-dev, libxcursor-dev, libxi-dev, libxfixes-dev, libxss-dev, libxtst-dev, libxkbcommon-dev, libxcb1-dev, libasound2-dev, libpulse-dev, libpipewire-0.3-dev, libdbus-1-dev, libudev-dev, libdrm-dev, libgbm-dev, libegl-dev, libgl-dev, libgles-dev, libwayland-dev, libdecor-0-dev, libvulkan-dev, libusb-1.0-0-dev, libpulse0, libwayland-client0, libwayland-cursor0, libwayland-egl1
- libc/kernel/GCC/libstdc++ packages provide the target ABI, compiler headers and static C++ runtime.
- X11/XCB/Xrandr/Xrender/Xcursor/Xi/Xfixes/Xss/Xtst/xkbcommon are SDL window/input/clipboard/display integrations.
- ALSA/Pulse/PipeWire provide SDL audio routes; dbus/udev/libusb support desktop and controller/device discovery.
- Wayland client/cursor/EGL, libdecor and xkbcommon provide Wayland windows, input and decorations.
- DRM/GBM/EGL/GL/GLES are SDL platform/backend dependencies; Vulkan supplies the Linux renderer/FFX interface.
The cross toolchain explicitly binds runtime sonames for SDL dlopen. Direct application #include searches alone would miss them.
See cmake/toolchains/linux-x86_64-clang-cross.cmake and the pinned SDL cmake/sdlchecks.cmake / cmake/FindLibUSB.cmake.
CI apt/vcpkg recipes select subsets of these plus Ninja, glslc and Vulkan headers/loader. No system package was uninstalled.

UNCERTAIN / FEATURE-SIZE DECISIONS LEFT FOR YOU
1. .NET runtime trimming for LibOrbisPkg/Android: the cached single-file Mac extractor is 80,200,750 bytes.
   The library is required, but individual framework assemblies may be removable with a separate trim/reflection/JNI audit.
   Kept the runtime intact; a file-name search cannot prove that dynamically reached framework code is unnecessary.
2. Windows GPU SDK/runtime pruning (Streamline plugins, NGX/DLSS, XeSS/XeLL, both FidelityFX generations, OpenXR, optional ReShade):
   live calls and dynamic loads exist. Driver/plugin transitive dependencies and the hardware matrix were not exercised here.
   Removing any provider also removes a supported feature or hardware path; no package-size saving is asserted without local binaries.
3. Optional SDL Linux system backends (especially DRM/GBM/EGL/GL/GLES) and Windows build-time Vulkan loader discovery:
   they remain part of the configured dependency graph. Deciding to disable backends or alter Windows SDK discovery needs native
   validation; textual application calls do not establish that every SDL window-system/driver fallback is unreachable.
4. The desktop second-opinion Whisper model is 190,098,681 bytes and is actually loaded by the default rescue path.
   Kept for recognition behavior. Dropping that feature is a product choice, not an unused-dependency removal.
